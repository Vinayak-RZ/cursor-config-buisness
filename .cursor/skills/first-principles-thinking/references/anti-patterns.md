# Anti-patterns — first-principles skill

The goal is accuracy, not rebellion.

## 1. Contrarian theater

Rejecting an industry because rejection sounds smart. Many conventions solve real problems (trust, safety, procurement, liability).

**Fix.** Keep what survives decomposition. Remove only what does not.

## 2. Empty abstraction

Phrases like "rethink from the ground up" without named assumptions, constraints, or a new design.

**Fix.** State assumptions. Name hard vs soft constraints. Show the rebuilt design. Give the first test.

## 3. Ignoring execution

Elegant physics that the user cannot run given cash, team, regulation, or time.

**Fix.** Rebuild inside hard constraints. Challenge soft ones. Recommendations must be executable.

## 4. Treating the user's wording as the problem

"Should I build an app?" is a method. The job might be "get this outcome to this buyer."

**Fix.** Reframe to the outcome before designing the form.

## 5. Optimizing instead of redesigning

Improving each step of a legacy process without asking whether the process should exist.

**Fix.** Musk order: question requirements → delete → then optimize / speed / automate.

## 6. Throwing away empirical evidence

Rejecting SaaS subscriptions, marketplaces, or BMC blocks because they were not derived live in this chat.

**Fix.** Treat proven patterns as data. Test whether they reflect hard reality or historical momentum. Pair with `business-model` pattern cards.

## 7. Iconic-example cosplay

Every analysis becomes rockets, Tesla, or "be like Elon."

**Fix.** Steal the *structure* (decompose cost, function over form). Use the user's industry analog.

## 8. Ending without a decision

A lecture on epistemology with no recommendation.

**Fix.** End with a choice, a priority order, or an experiment plus kill criterion.

## Self-check

- Real goal named?
- Assumptions listed?
- Soft constraint mislabeled as hard?
- Executable this week?
- Avoided sounding profound?
