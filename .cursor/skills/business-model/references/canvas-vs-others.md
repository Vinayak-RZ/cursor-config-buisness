# Canvas routing — do not duplicate other skills

This repo already has Lean Canvas and Product Strategy. Use the right artifact.

## Magretta (required conceptually, any canvas)

Business model = story of how the enterprise works (who, value, how we get paid, economic logic).  
Strategy = how you deal with competitors.  
Do not call a BMC a strategy. After the model, leftover competitive choices go to `product-strategy`.

## Business Model Canvas (this skill)

Osterwalder / Strategyzer. Best for **established** businesses, investor materials, and seeing operational pieces (partners, resources, activities) in one view.

Known gaps (do not pretend they are filled):

- No vision / "why we get up"
- No explicit trade-offs (what we will not do)
- Weak defensibility ("resources" ≠ moat)
- No metrics
- Key partnerships/resources often low-value for day-zero startups

## Lean Canvas (`lean-canvas`)

Ash Maurya. Replaces partners/activities/resources with problem / solution / unfair advantage. Faster for **hypothesis testing**. Gaps: redundancy (problem vs segment, solution vs UVP), thin strategy (no vision/trade-offs), unfair advantage too narrow.

## Product Strategy Canvas (`product-strategy`)

Huryn-style 9 sections: vision, segments, relative costs, value prop, trade-offs, metrics, growth, capabilities, can't/won't. This is **strategy**, not the P&L logic. Pair with this skill's cost/revenue blocks when the user needs both.

## Startup Canvas (not installed)

Product strategy + cost/revenue. Intentionally **not** in this repo — `product-strategy` + this skill (or `lean-canvas`) cover it without a third overlapping canvas.

## Monetization (`monetization-strategy`)

Brainstorms 3–5 **revenue** mechanics. Use when the user only wants how to charge. Use **this skill** when they need the whole system (who/how/costs/partners), not just the price tag.
